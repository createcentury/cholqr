# Pre-registration: cholqr 0.5 under TF32 on tensor-core hardware: residual, orthogonality, range (2026-11-12)

Written and committed, together with the script and judge `benchmarks/tf32_hw_range.py`, before any run (smoke
included). A smoke run (`--smoke`) prints timings only and writes nothing.

## Question

Sec. 6.11 of the rounding note measured **plain** TF32 (emulated on the CPU): the range of $Q$ is lost in proportion to
cond, $\sin\theta \approx 1.2 \cdot 10^{-4}\,\mathrm{cond}$, because $Y$ is rounded to TF32 before any CholeskyQR step. cholqr 0.5
splits every GEMM operand as $A = A_h + A_l$ (3xTF32), which represents the input to about $t^2 = 4u$. A post-hoc CPU
emulation of that path (reviewer, `/tmp/refchk/comp.py`, cond $10^2$–$10^7$, seed 0) gave $\sin\theta = 1.3$–$6.9 \cdot 10^{-8}\,\mathrm{cond}$,
FP32 level, but did not model tensor-core accumulation. Does the 0.5 path keep FP32-like range on real hardware?

## Setup

- Hardware: one NVIDIA RTX 4090 (RunPod), torch 2.8 / CUDA 12.8 image, cholqr 0.5.0 from this repository (source).
- Grid (identical to the `resid` part of `benchmarks/downstream_orth.py`, same seeds, bit-identical inputs): $1024 \times 64$
  and $4096 \times 276$; geometric, two-cluster, staircase spectra; nominal cond $10^2, 10^{2.5}, \dots, 10^8$; 2 seeds;
  156 inputs; input rounded to FP32.
- Variants on the GPU: `c3_scqr3` (precision "high", default call, 3xTF32 active), `c3_scqr3_raw`
  (`on_breakdown="ignore"`), `plain_scqr3` (precision "high" with `core._tf32_active` patched to `False`: plain TF32
  products on the tensor cores; control), `fp32_scqr3`, `fp32_scqr3_raw` (precision "highest").
- Variants on the CPU (Apple M4, same script, `--device cpu`): `emu3_scqr3`, `emu3_scqr3_raw` = the reviewer's
  emulation of the 0.5 split (each hi/lo operand rounded to TF32, FP64 accumulation, FP32 result).
- Metrics (FP64, CPU, functions of `downstream_orth.py`): orthogonality $\|Q^TQ - I\|_F$; residual
  $\|\mathrm{fl}(Y) - QR\|_F / \|\mathrm{fl}(Y)\|_F$; $\sin\theta$ = largest principal angle between range($Q$) and range($\mathrm{fl}(Y)$),
  the latter from an FP64 Householder QR. Broken := orthogonality $> 0.1$ or non-finite.
- Validity: `core._tf32_active` must be True for every `c3` call and False for every `fp32` call (else INVALID).

## Predictions (judged by `tf32_hw_range.py --judge DIR`)

- **H1** `c3_scqr3`, non-broken: median of $\sin\theta/\mathrm{cond}$ in $[10^{-8}, 10^{-7}]$.
- **H2** `c3_scqr3`, non-broken: $\sin\theta \le 3 \cdot 10^{-7}\,\mathrm{cond}$ in $\ge 98\%$ of runs.
- **H3** Per input (both non-broken): $\sin\theta(\texttt{c3\_scqr3}) \le 3\,\sin\theta(\texttt{fp32\_scqr3})$ in $\ge 90\%$.
- **H4** Per input (both non-broken): hardware `c3_scqr3` / CPU emulation `emu3_scqr3` ratio of $\sin\theta$ in $[1/3, 3]$ in $\ge 90\%$.
- **H5** `c3_scqr3`, non-broken: residual max $\le 10^{-5}$ and median $\le 10^{-6}$.
- **H6** (control) `plain_scqr3` at cond $\le 10^{3.5}$: median $\sin\theta/\mathrm{cond}$ in $[3 \cdot 10^{-5}, 5 \cdot 10^{-4}]$ (emulated plain TF32: $1.2 \cdot 10^{-4}$).
- **H7** `fp32_scqr3`, non-broken: $\sin\theta \le 3 \cdot 10^{-7}\,\mathrm{cond}$ in $\ge 98\%$ (CPU FP32: max $2.0 \cdot 10^{-7}\,\mathrm{cond}$).
- **H8** `c3_scqr3` (default call): orthogonality $\le 10^{-4}$ in $\ge 90\%$ of the 156 runs.

**Decision rule.** "cholqr 0.5's 3xTF32 keeps FP32-like range on the RTX 4090" = VALID and H1 and H2 and H3.
H4–H8 are reported individually. One GPU, one torch version: a PASS is a measurement on this configuration, not a
guarantee for other GPUs.
